# RPGCore

Paper 서버용 RPG 플러그인. 스탯/레벨, 직업, 순위표, 파티, 플레이어 간 거래,
업적과 칭호, 수집 도감, 1:1 대결, **골드 경매장**, **길드·영지·길드전**, 소지 무게,
장비 내구도 페널티, 연쇄 벌목, 모루 커스텀 강화, 근접 채팅, **Discord 알림**을
한 덩어리로 제공합니다.
이름표와 플레이어 목록, 아이템 툴팁에도 RPG 정보가 함께 표시됩니다.

**`/menu` 하나면 됩니다.** 기능마다 명령어를 외울 필요 없이 상자 창 하나에서
모든 화면으로 이동합니다.

**기본으로 들어 있는 콘텐츠** — 직업 15종(3단계), 업적 41개, 칭호 48개,
도감 20분류 363종, 모루 강화 16종. 전부 설정 파일이라 코드 수정 없이 늘릴 수 있습니다.

- **jar 하나가 전부입니다.** 데이터팩도, 다른 플러그인도, 외부 라이브러리도 필요 없습니다.
- **전부 서버 사이드 로직**이라 자바와 베드락(Geyser) 플레이어가 **완전히 동일하게** 동작합니다.
- 설정은 `config.yml` 한 파일. 대부분 `/rpgcore reload` 로 재시작 없이 반영됩니다.

## 설치

**요구사항: Paper 26.2 이상, Java 25** (Paper 26.2 자체가 Java 25를 요구합니다.)

1. `plugin/` 에서 빌드 → `plugin/target/rpgcore-plugin-2.6.0.jar`
   ```
   cd plugin && JAVA_HOME=/path/to/jdk-25 mvn package
   ```
2. jar 를 서버 `plugins/` 에 넣고 재시작.
3. 끝. `plugins/RPGCorePlugin/` 에 설정 파일이 자동 생성됩니다.
   - `settings.yml` — 최대 레벨, 경험치 곡선, 인챈트 한계, 기능 on/off (**주로 여기만**)
   - `jobs.yml` — 직업 정의
   - `config.yml` — 아이템 분류, 모루 조합법 등 세부 설정

기동 로그에 아래처럼 뜨면 정상입니다.

```
[RPGCorePlugin] Weight table loaded: 280 materials; anything unlisted weighs 1.
[RPGCorePlugin] Tree felling: 22 log types, 7 tools.
[RPGCorePlugin] Anvil recipes loaded: 16.
[RPGCorePlugin] Jobs loaded: 15.
[RPGCorePlugin] Achievements loaded: 41.
[RPGCorePlugin] Collection log loaded: 20 categories, 363 entries.
[RPGCorePlugin] Parties loaded: 0.
```

숫자가 위와 다르면 그만큼 건너뛴 것입니다. **이 서버 버전에 없는 아이템이나 태그는
경고 한 줄을 남기고 넘어가므로**, 기동 로그에 `WARN` 이 없다면 설정이 전부 읽힌 것입니다.

**(선택) 근접 음성**: [Simple Voice Chat](https://modrinth.com/plugin/simple-voice-chat) 을 함께 깔면 실제 음성이 됩니다.
그쪽 `voice_chat_distance` 와 이쪽 `proximity-chat.range` 가 어긋나면 기동 로그가 경고합니다.
(음성은 자바 클라이언트 모드가 필요합니다. 베드락은 근접 **텍스트** 채팅으로 동작합니다.)

## 기능

### `/menu` — 전부 여기서
상자 창 하나에서 스탯 · 직업 · 칭호 · 도감 · 업적 · 순위표 · 파티 · 길드 · 길드 보관함 ·
경매장 · 우편함으로 바로 갑니다. 화면끼리 서로 오갈 수 있으므로 명령어를 몰라도 기능을 전부 찾을 수 있습니다.

가운데 위에 레벨 · XP · 무게가, 아래에 골드 잔액과 우편함이 붙습니다. 우편함에 받을 것이
있으면 아이콘이 엔더 상자로 바뀌므로 따로 알려 주지 않아도 눈에 띕니다.

`settings.yml` 에서 끈 기능은 **자리를 비우지 않고 회색 칸으로 남습니다.** 서버마다 버튼
위치가 달라지면 익힌 배치가 소용없어지기 때문입니다.

### 길드
`/guild create <이름>` 으로 창설합니다(기본 1,000골드). 파티가 하룻저녁 모임이라면 길드는
**공동 보관함과 땅을 가진 조직**입니다.

**공동 보관함** — `/guild vault` 또는 `/menu` → 길드 보관함. 기본 54칸(큰 상자 한 개)이고
`vault-rows` 로 줄입니다. 길드원 전원이 **같은 상자 하나**를 봅니다. 두 사람이 동시에 열어도
각자 사본을 보는 게 아니라 진짜 같은 컨테이너라서, 같은 아이템을 둘이 집어 갈 수 없습니다.
누군가 창을 닫을 때마다 디스크에 기록하므로 서버가 갑자기 내려가도 남습니다.

**금고와 투자** — `/guild deposit <금액>` 으로 누구나 금고에 넣고, 인출과 사용은 길드장만
할 수 있습니다. `/guild invest <금액>` 은 금고의 골드를 **영지 반경**으로 바꿉니다(기본
500골드당 +1블록, 최대 96).

이 둘의 관계가 길드 운영의 핵심입니다. **금고에 쌓아 둔 골드는 전쟁에서 지면 통째로
넘어가지만, 투자한 골드는 이미 땅이 되어 빼앗기지 않습니다.** 쌓아 둘지 넓힐지가 곧
"큰 전리품을 내걸고 버틸지, 못 빼앗기는 넓은 집을 지을지"의 선택이 됩니다.

**영지** — `/guild banner` 로 영지 깃발을 사고(기본 2,000골드), **길드장이** 원하는 자리에
세우면 그 지점 반경 32블록(정사각형, 높이 무제한)이 영지가 됩니다.
**깃발은 길드당 하나뿐입니다** — 전쟁이 "상대 깃발을 부수면 승리"인데 깃발이 여럿이면
무엇을 부숴야 이기는지가 정해지지 않기 때문입니다.

- 길드에 속하지 않은 사람은 **영지 안의 블록을 부술 수 없습니다.** 블록 설치, 물·용암 붓기,
  폭발과 불타기도 함께 막습니다 — 크리퍼가 대신 부숴 준다면 보호라고 할 수 없으니까요.
  영지 밖 블록은 같은 폭발이어도 그대로 터집니다. (전쟁 중인 상대만 예외 — 아래)
- 영지 안의 **길드원은 이동속도 · 채굴속도 · 점프 버프**를 받습니다. 이미 더 센 효과를
  갖고 있으면 덮어쓰지 않으므로, 신속 물약을 마신 채 들어와도 손해 보지 않습니다.
- 영지 안에서는 **작물이 한 단계 더 자랍니다.** 자연 성장이 일어날 때 거기에 얹는 방식이라
  영지가 아무리 넓어도 실제로 자라는 작물 수만큼만 비용이 듭니다.
- 깃발을 부수면 영지가 사라지고 깃발을 돌려받습니다. 깃발이 다른 경로로 없어져도(피스톤,
  월드에디트 등) 순찰 검사가 찾아내 영지를 해제합니다.
- 영지끼리는 서로 `gap-between-claims` 만큼 떨어져야 합니다. 경계가 붙으면 블록 하나를 두고
  다투게 되는데, 영지는 바로 그 다툼을 없애려고 있는 것이기 때문입니다.
- 깃발끼리는 **최대 반경 기준으로** 떨어뜨립니다(기본 208블록). 현재 반경이 아니라 앞으로
  커질 수 있는 최대치로 자리를 잡아 두므로, 돈을 내고 산 확장이 이웃 때문에 막히는 일이
  생기지 않습니다.
- 운영자(`rpgcore.admin`)는 모든 영지에서 자유롭게 작업할 수 있습니다.

### 길드전
`/guild war <길드 이름>` 으로 선전포고합니다(금고에서 기본 5,000골드, 져도 돌려받지 않음).

1. **준비 시간** (기본 10분) — 선포는 됐지만 아직 깃발을 건드릴 수 없습니다. 이게 없으면
   "선포"와 "승리"가 같은 행동이 되어, 상대가 접속해 있지 않은 시간을 노리는 것이 최적
   전략이 됩니다. 방어 측이 모일 시간입니다.
2. **교전** (기본 60분) — **양쪽 영지가 서로에게 열립니다.** 상대 영지의 블록을 부술 수
   있고, 교전 중인 길드의 땅은 폭발 보호도 풀려 TNT 를 공성 수단으로 쓸 수 있습니다.
3. **승부** — **상대 깃발을 먼저 부수는 쪽이 이기고, 진 길드 금고의 100%를 가져갑니다.**
   시간 안에 승부가 안 나면 무승부이고 골드는 움직이지 않습니다.

전쟁은 **양방향**입니다. 선포하면 우리 깃발도 똑같이 위험해지므로 "제일 약한 길드에
선포하면 공짜"가 되지 않습니다.

**전쟁 중에는 금고에서 골드를 뺄 수 없습니다** — 인출도, 투자도 막힙니다(넣는 것은 가능).
선포 시점의 금고가 곧 판돈이기 때문입니다. 이게 없으면 선포당한 쪽이 준비 시간에 금고를
비워 버리면 그만이고, 그러면 전리품이라는 게 없어집니다.

같은 이유로 **전쟁 중에 빠져나가는 모든 경로가 항복 처리**됩니다 — 자기 깃발을 스스로
부수는 것, 깃발이 다른 이유로 사라지는 것, 그리고 **길드를 해체하는 것**까지. 해체가
빠져 있으면 "질 것 같으면 해체하고 다시 창설"이 지는 것보다 항상 이득이 됩니다.

같은 상대와 다시 붙기까지는 재사용 대기시간이 있고(기본 24시간), 이 대기시간은 **서버를
재시작해도 유지됩니다.** 전쟁 중에는 깃발을 새로 세울 수 없습니다 — 쳐들어오는 쪽 밑에서
목표물을 옮길 수 있으면 안 되니까요.

### 경매장
`/menu` → 경매장, 또는 `/auction`. 골드를 실제로 쓸 곳이자, 서버에 쌓인 골드가 빠져나가는
곳입니다.

- `/auction sell <시작가> [즉시구매가]` — **손에 든 물건**을 올립니다. 즉시구매가를 적지
  않으면 순수 입찰 경매가 됩니다.
- 좌클릭으로 입찰, 우클릭으로 즉시구매. 자기 물건은 우클릭으로 내립니다.
- 입찰하는 순간 골드를 **실제로 걷어 갑니다.** 그래서 밀려난 사람은 그 자리에서 전액을
  돌려받고, 낼 수 없는 입찰이라는 것이 존재하지 않습니다.
- 마감 직전 입찰이 들어오면 종료가 미뤄집니다(`anti-snipe-seconds`). 없으면 "마지막 순간에
  찔러 넣기"가 최선의 전략이 되어 값이 아니라 핑으로 이기는 경매가 됩니다.
- **입찰이 하나라도 들어오면 판매자는 물건을 내릴 수 없습니다.** 그렇지 않으면 모든 입찰이
  판매자 기분에 거는 도박이 됩니다.

수수료가 두 가지입니다. 등록 수수료는 올릴 때 받고 유찰돼도 돌려주지 않으며(빈 물건 도배
방지), 판매 수수료는 팔렸을 때 낙찰가에서 뗍니다. 둘 다 `config.yml` 의 `auction:` 에 있고,
0 으로 두면 골드가 서버에 쌓이기만 합니다.

### 우편함
낙찰된 물건, 판매 대금, 밀려난 입찰금, 유찰된 물건, 무승부로 끝난 대결의 판돈 — **받을
사람이 접속 중이 아닐 때 생기는 것**은 전부 우편함(`mailbox.yml`)에 들어가고 다음 접속에
자동으로 전달됩니다. `/menu` 의 우편함 칸이나 `/auction collect` 로도 받습니다.

UUID 로 보관하므로 닉네임을 바꿔도 따라옵니다. 인벤토리가 가득 차면 **바닥에 버리지 않고**
그대로 두고 알려 줍니다 — 용암 위에 서 있는 사람 발밑에 떨구는 것보다 낫습니다.

### 스탯 / 레벨
STR · DEX · VIT · AGI · LUCK. 레벨업마다 포인트를 받아 `/stats` 창에서 찍습니다.
찍은 값은 바닐라 어트리뷰트에 그대로 반영됩니다.

한 스탯이 한 가지만 하면 고를 이유가 없으므로, 스탯마다 **역할이 두세 개씩** 있습니다.

| 스탯 | 효과 | 20포인트 기준 |
|---|---|---|
| STR | 공격력, 공격 넉백, 최대 소지무게 | 공격력 +7 (다이아검 7 → 14), 넉백 +40%, 무게 +160 |
| DEX | 공격 속도, 채굴 속도, 휩쓸기 피해 | 초당 타격 +30%, 채굴 +16%, 휩쓸기 +20% |
| VIT | 최대 체력, 넉백 저항 | 체력 +40(20칸), 넉백 저항 +16% |
| AGI | 이동속도, 점프력, 안전 낙하 거리 | 이동 +24%, 점프 +14%, 낙하 3블록 더 |
| LUCK | 행운, **처치 보상 2배 확률** | 행운 +8, 골드 2배 확률 40% |

**LUCK 이 실제로 쓰이게 했습니다.** 바닐라 `luck` 어트리뷰트는 낚시 전리품 표에만
영향을 주기 때문에, 그것만으로는 아무도 찍지 않습니다. 이제 몬스터를 처치할 때
LUCK 에 비례한 확률로 **골드 보상이 2배**가 되고, 터지면 액션바에 `✦ 행운! 보상 2배`
가 뜹니다. 확률에는 상한(`economy.luck-double-chance-max`, 기본 60%)이 있습니다 —
"항상 2배"에 닿는 순간 그건 운이 아니라 **모두가 찍어야 하는 고정 배수**가 되고,
선택이 사라집니다.

#### 소프트캡 — 왜 한 스탯만 찍으면 손해인가

포인트당 효과가 끝까지 일정하면, 최적 전략은 언제나 **한 스탯에 전부 몰기**입니다.
그래서 `config.yml` 의 `stats.soft-cap`(기본 20)을 넘는 포인트는 **35%만** 적용됩니다.

```
실효값 = min(포인트, 20) + (포인트 - 20) × 35%

STR 20 → 실효 20     (공격력 +7.0)
STR 40 → 실효 27     (공격력 +9.5)   ... 포인트는 2배인데 효과는 1.36배
STR 20 + VIT 20 → 실효 20/20 (공격력 +7.0, 체력 +40)
```

40포인트를 한 곳에 몰면 27, 둘로 나누면 20+20 = 40 어치입니다. **넓게 찍는 쪽이 항상
이득이지만**, 특화가 필요한 상황(예: 무게가 모자란 광부)에서는 몰아 찍는 선택도
여전히 유효합니다. 그게 선택이 되도록 깎는 비율을 0 이 아니라 35%로 잡았습니다.

`/stats` 창은 찍은 포인트와 실효값을 같이 보여주고, 캡을 넘긴 스탯에는
`실효 31.9 — 20 초과분은 35%만 적용됩니다` 한 줄이 붙습니다.
`soft-cap: 0` 으로 두면 곡선이 꺼지고 예전처럼 완전 선형이 됩니다.

#### 레벨 곡선

XP는 몹 처치(15), 벌목한 원목(2), `/rpgcore givexp` 로 들어옵니다.
기본 곡선(`80 / 30 / 1.022`)은 이렇게 됩니다.

| | Lv2 | Lv10 | Lv20 | Lv30 | Lv50 | Lv100 |
|---|---|---|---|---|---|---|
| 필요 XP | 80 | 380 | 917 | 1,692 | 4,320 | 25,479 |
| 누적 | 80 | 2,270 | 8,660 | 21,795 | 80,335 | 708,856 |

레벨 50까지 누적 약 80,000 XP — 몹만 잡는다면 5,400마리입니다. 배수가 1.0(직선)이면
50레벨이 10레벨과 똑같은 무게로 느껴지지만, 1.022 에서는 마지막 레벨이 10레벨의 10배가
들어서 **초반은 빠르게 흐르고 후반 레벨 하나하나가 사건이 됩니다.**

**레벨은 체력을 조금만 줍니다**(레벨당 1). 예전처럼 레벨당 2였을 때는 레벨 50에서
아무 것도 안 찍고 체력 120(60칸)이 되어 **VIT 를 찍을 이유가 사라졌습니다.**
**최대 레벨**과 **경험치 곡선**은 `settings.yml`, 스탯 계수는 `config.yml` 의
`stats:` 블록에서 정합니다.

### 직업 (클래스)
`/job` 으로 고릅니다. 직업은 **스탯 보너스 + 어트리뷰트 + 경험치 배율 + 소지무게**를 줍니다.

직업은 **3단계 15종**입니다. 위로 갈수록 강해지는 게 아니라, **더 뾰족해집니다.**

**1단계 (레벨 1)** — 방향만 정해 줍니다. 약점이 없습니다.

| 직업 | 주는 것 |
|---|---|
| 전사 | STR+3 VIT+2, 최대체력 +4, 넉백저항 +15%, 무게 +30 |
| 궁수 | DEX+3 AGI+2, 이동속도 +8%, 상호작용 사거리 +0.5 |
| 광부 | STR+2 VIT+1, 채굴 +25%, 수중 채굴 +100%, 산소 +2, 무게 +70, XP x1.1 |
| 나무꾼 | STR+2 DEX+2, 채굴 +15%, 무게 +50, XP x1.15 |
| 어부 | LUCK+4 VIT+1, 산소 +4, 수중 이동 +60% |

**2단계 (레벨 12)** — 한 가지를 확실히 잘하는 대신 **다른 하나를 포기합니다.**

| 직업 | 주는 것 | 포기하는 것 |
|---|---|---|
| 기사 | VIT+4 STR+2, 방어 +4, 강도 +2, 체력 +6, 넉백저항 +40%, 무게 +60 | 이동속도 −6% |
| 도적 | AGI+4 LUCK+3, 이동 +14%, 공속 +12%, 웅크리기 +50% | 최대체력 −4 |
| 사냥꾼 | DEX+3 AGI+3 LUCK+1, 사거리 +1.0, 안전낙하 +3, 이동 +6% | — (범용형) |
| 대장장이 | STR+4 VIT+2, **무게 +160**, 방어 +2, 채굴 +10% | 이동속도 −4% |
| 탐험가 | AGI+5 LUCK+1, 이동 +18%, 점프 +15%, 안전낙하 +5, 계단 +0.5 | 공격력 −1 |

**3단계 (레벨 30)** — 극단적인 특화. **약점이 분명한 대신 강점이 큽니다.**

| 직업 | 주는 것 | 포기하는 것 |
|---|---|---|
| 수호자 | VIT+7 STR+2, 방어 +7, 강도 +4, 체력 +12, 넉백저항 +70%, 폭발저항 +50%, 무게 +120 | 이동속도 −10% |
| 광전사 | STR+7 DEX+3, 공격력 +30%, 공격넉백 +50%, 휩쓸기 +50%, 무게 +40 | 체력 −6, 방어 −2 |
| 암살자 | DEX+6 AGI+4, 공속 +30%, 이동 +20%, 웅크리기 +80% | **체력 −8** |
| 현자 | LUCK+6 VIT+2 DEX+2, 행운 +3, **XP x1.4** | 공격력 −15% |
| 파수꾼 | STR+3 VIT+4 DEX+3 AGI+2, 방어 +3, 체력 +6, 무게 +80, XP x1.1 | — (균형형, 어느 쪽도 최고는 아님) |

몇 가지 설계 의도:

- **3단계가 1단계의 상위 호환이 아닙니다.** 암살자는 체력이 8(4칸) 깎이고, 광전사는
  방어구를 벗다시피 합니다. 레벨 30에 도달했다고 무조건 갈아타는 게 정답이 아니게
  하려고 실제 페널티를 넣었습니다.
- **직업 보너스도 소프트캡에 함께 들어갑니다.** 이미 STR 20을 찍은 사람이 광전사
  (STR+7)를 고르면 그 7은 35%만 들어옵니다. 자기가 안 찍은 쪽을 메워 주는 직업이
  포인트 효율이 더 좋습니다 — 직업 선택에 실제 고민이 생깁니다.
- **`multiply` 는 합계에 대한 비율**이라 `add` 보다 훨씬 강합니다. 그래서 이동속도처럼
  넘치기 쉬운 값에는 작게(6~20%), 무게처럼 안전한 값에는 크게 잡았습니다.

직업이 주는 스탯은 직접 찍은 포인트 **위에 더해집니다**. `/stats` 창에서 `VIT: 5 (2 +3 직업)`
처럼 분리해서 보여줍니다. 직업을 바꾸면 이전 직업의 보너스는 전부 해제됩니다.
전부 `jobs.yml` 에 있으므로 코드 수정 없이 추가·수정할 수 있습니다.

### 순위표 (리더보드)
`/leaderboard [항목]` — 스코어보드에 기록되는 값은 전부 순위로 볼 수 있습니다.

| 묶음 | 항목 |
|---|---|
| 성장 | `level`, `gold` |
| 스탯 | `str` `dex` `vit` `agi` `luck` |
| 진행도 | `mob-kills` `blocks-mined` `ores-mined` `logs-chopped` `fish-caught` `duels-won` `gold-earned` `collected` |

자기 순위가 표시 범위 밖이면 맨 아래에 따로 붙여줍니다.

데이터는 이미 쓰고 있는 **스코어보드 미러**에서 읽습니다. 별도 저장소가 없고,
**접속 중이 아닌 플레이어도 집계**됩니다. 결과는 몇 초간 캐시되므로 명령어를 연타해도
서버에 부담이 없습니다.

### 파티
`/party create [이름]` 으로 만들고 초대합니다. **파티는 서버를 재시작해도 유지됩니다.**

- **이름** — 파티마다 고유한 이름을 붙입니다. 이름은 파티 채팅 접두사, 초대 문구, `/party list`
  에 그대로 쓰입니다. `/party name <새이름>` 으로 바꿉니다(파티장만). 색코드는 제거되고,
  이미 쓰이는 이름이나 길이 초과(기본 16자)는 거부됩니다.
- **경험치 공유** — 파티가 얻은 XP 는 사거리(기본 50블록) 안에 있고 **접속 중인** 파티원끼리만
  나눕니다. 오프라인 파티원은 몫도 받지 않고 인원 보너스에도 들어가지 않습니다.
  `총량 = 원래 XP × (1 + 0.05 × (접속 인원-1))`
  예) 3명 접속 중 10 XP → 11 XP → 각자 4 XP. 한 명이 나가면 → 10.5 XP → 각자 5 XP.
- **아군 공격 차단** — 기본적으로 파티원끼리는 근접·투사체 피해가 들어가지 않습니다.
- **파티 채팅** — `/p <메시지>` 는 거리와 무관하게 접속 중인 파티원 전체에게 갑니다.
- 오프라인 파티원도 `/party list` 에 보이고 추방할 수 있습니다. 파티장이 `/party leave` 하면
  다음 사람에게 파티장이 넘어가고, 파티를 없애려면 `/party disband` 를 씁니다.

### 플레이어 간 거래
`/trade <플레이어>` 로 요청하고, 상대가 `/trade accept` 하면 **양쪽이 같은 상자 UI 하나**를
함께 봅니다.

```
 내가 내놓는 것        상대가 내놓는 것
 ┌───────────┐ │ ┌───────────┐
 │ ■ ■ ■ ■   │ │ │   ■ ■ ■ ■ │
 │ ■ ■ ■ ■   │ │ │   ■ ■ ■ ■ │   왼쪽 4칸 = 내 물건
 │ ■ ■ ■ ■   │ │ │   ■ ■ ■ ■ │   오른쪽 4칸 = 상대 물건
 │ ■ ■ ■ ■   │ │ │   ■ ■ ■ ■ │
 └───────────┘ │ └───────────┘
   [내 확정]    │   [상대 확정]
```

- 화면을 **하나만** 쓰므로 한쪽에게만 다르게 보이는 일이 구조적으로 불가능합니다.
- 자기 칸에만 물건을 올릴 수 있습니다. 상대 칸 클릭, 드래그, 더블클릭 모으기는 전부 막힙니다.
- 물건이 바뀌면 **양쪽 확정이 자동으로 풀립니다.** 확정 직전에 몰래 바꿔치기할 수 없습니다.
- 양쪽이 확정하면 교환됩니다. 받을 공간이 모자라면 **아무것도 옮기지 않고** 알려줍니다.
- 창을 닫거나, 접속을 종료하거나, 죽거나, `/trade cancel` 하거나, 서버가 꺼지면
  **올려둔 물건은 전부 주인에게 돌아갑니다.**

### 업적과 칭호
목표를 달성하면 골드/경험치 보상과 **칭호**가 들어옵니다. 칭호는 `/titles` 에서 골라
이름 옆에 붙입니다 — 머리 위 이름표와 Tab 목록 양쪽에 나옵니다.

**업적 41개, 칭호 28개**가 기본으로 들어 있습니다. 도감 20개 분류에 걸린 칭호까지 하면
서버에 **칭호가 48개** 돌아다닙니다 (`/rpgcore check` 가 세어 줍니다). 대부분 하나의 기준을 여러 단계로
나눠 두었으므로, 처음 한 칸은 금방 채워지고 마지막 칸은 오래 걸립니다.

| 측정 기준 | 단계 | 마지막 목표 | 마지막 칭호 |
|---|---|---|---|
| 레벨 | 9 | 100 | `[한계를 넘은 자]` |
| 몬스터 처치 | 5 | 20,000마리 | `[종결자]` |
| 대결 승리 | 5 | 200승 | `[무패의 전설]` |
| 블록 채굴 | 4 | 100,000개 | `[대굴착자]` |
| 광석 채굴 | 4 | 5,000개 | `[심층 채굴자]` |
| 누적 골드 | 4 | 1,000,000G | `[황금 손]` |
| 도감 등록 | 4 | 250종 | `[박물학자]` |
| 원목 벌목 | 3 | 10,000개 | `[숲을 민 자]` |
| 물고기 낚기 | 3 | 2,500마리 | `[바다의 인내]` |

그 중 **5개는 서버에서 딱 한 명**만 가져가는 기록입니다 (`first-only`) — 레벨 25
`[개척자]`, 레벨 60 `[선구자]`, 25승 `[초대 챔피언]`, 광석 2,500개 `[광맥왕]`,
도감 200종 `[초대 관장]`. 이건 **경쟁**이지 목표가 아니라서, 두 번째로 달성한 사람은
아무것도 받지 못합니다.

- `first-only: true` 를 붙이면 **서버에서 딱 한 명**만 가져가는 기록이 됩니다.
  먼저 달성한 사람의 이름이 `records.yml` 에 남고 `/achievements` 에 표시됩니다.
  (동시에 달성해도 기록을 먼저 쓴 쪽만 인정되므로 두 명이 같은 최초를 가져갈 수 없습니다.)
- 칭호가 걸린 업적과 서버 최초 업적은 서버 전체에 알립니다.
- 창작 모드로 부순 블록과 낚은 물고기는 세지 않습니다.
- `/achievements` 로 항목별 진행도를, `/titles` 로 칭호 목록(못 얻은 것은 회색)을 봅니다.

### 골드
업적 보상과 몬스터 처치·레벨업으로 들어오고, **경매장에서 쓰고** 대결에 걸 수 있는 재화입니다.
스코어보드(`rpgcore.gold`)에 저장되므로 **경제 플러그인이 필요 없고** `/scoreboard` 로도
읽고 쓸 수 있습니다. `/gold` 로 확인, `/pay <플레이어> <금액>` 으로 주고받고,
`/rpgcore givegold` 로 지급·회수합니다.

주고받은 골드는 **'누적 획득'에 들어가지 않습니다.** 둘이서 같은 돈을 주거니 받거니 해서
`gold-earned` 업적을 파밍할 수 없습니다. `/pay` 자체를 막으려면
`economy.allow-player-transfer: false`.

### 수집 도감
**20개 분류, 363종**을 모으는 도감입니다. `/collection` 으로 엽니다.

| 묶음 | 분류 |
|---|---|
| 자원 | 원목 · 나무 가공 · 광물 · 주괴와 보석 · 돌과 광맥 |
| 자연 | 작물 · 꽃 · 묘목 · 버섯과 균사 · 산호 · 물고기 |
| 전리품 | 몬스터 전리품 · 머리 |
| 제작 | 양털 · 염료 · 방어구 한 벌 · 연장 · 음악 디스크 |
| 차원 | 네더 · 엔드 |

**분류를 다 채우면 칭호가 나옵니다** — 20개 분류 전부에 칭호가 걸려 있어서,
도감 자체가 칭호 20개짜리 콘텐츠입니다. 난이도에 맞춰 보상을 달리 잡았습니다:
돌과 광맥 300G, 음악 디스크 3,000G(21종을 전부 모아야 합니다), 엔드 4,000G.

- **인벤토리에 들어오기만 하면 등록**됩니다. 캐든, 만들든, 낚든, 상자에서 꺼내든 모두 인정.
- 한 장을 다 모으면 칭호와 보상이 들어오고 서버 전체에 알립니다.
- 모은 칸은 아이템 그대로, 못 모은 칸은 회색 유리로 보여 한눈에 진행도가 읽힙니다.
- 한 분류가 한 화면(45칸)을 넘으면 자동으로 쪽이 나뉩니다. `#minecraft:logs` 같은
  태그를 통째로 넣어도 뒤쪽이 잘리지 않습니다.
- 기존 서버에 처음 설치하면 **이미 들고 있던 물건은 조용히 등록**됩니다. 접속하자마자
  수십 줄이 쏟아지거나, 몇 달 전에 채운 칸으로 보상이 한꺼번에 나가지 않습니다.

### 1:1 대결
`/duel <플레이어> [건 것]` — 양쪽이 동의하고 같은 것을 걸어야 시작됩니다.

- 건 것을 비우면 그냥 대결, 숫자면 **골드**, `hand` 면 **손에 든 아이템**입니다.
  수락하는 쪽은 같은 것(아이템이면 같은 종류·같은 개수)을 내야 합니다.
- 시작할 때 양쪽에서 **미리 빼둡니다.** 걸어 둔 것은 대결 중에 쓰거나 버리거나
  거래로 넘길 수 없고, 서버가 갑자기 내려가도 그대로 돌려받습니다.
- **죽지 않습니다.** 치명타가 들어오는 순간 피해를 취소하고 승패로 처리하므로
  진 쪽도 아이템을 떨어뜨리지 않습니다. 끝나면 양쪽 다 체력이 회복됩니다.
- 시작 전 **3초 카운트다운**이 있고 그동안은 서로 때릴 수 없습니다. 수락하자마자
  한 대 맞고 시작하는 일이 없습니다.
- 시작할 때 양쪽 **체력을 채웁니다.** 한쪽이 반 칸이라 지는 대결은 대결이 아니니까요.
  (`duel.countdown-seconds`, `duel.heal-before-start` 로 끕니다)
- 도중에 접속을 끊으면 기권패입니다. 제한 시간(기본 5분)이 지나면 무승부로 끝나고
  건 것은 그대로 돌아갑니다.
- 파티원끼리도 대결할 수 있습니다(아군 공격 차단보다 대결이 우선).
- 월드의 PvP 가 꺼져 있으면 **신청 단계에서** 막힙니다.

### 소지 무게
인벤토리 + 방어구 + 보조손 41칸을 `개수 × 등급 무게` 로 계산합니다.
부하율에 따라 4단계이며, 단계가 바뀔 때만 어트리뷰트를 건드립니다.

| 부하율 | 이동속도 | 점프 | 추가 |
|---|---|---|---|
| ~70% | – | – | – |
| 70~100% | -10% | -15% | – |
| 100~130% | -25% | -40% | 허기 |
| 130%~ | -50% | -70% | 허기 + 채굴 피로 |

### 장비 내구도 → 성능
낡은 무기는 약하게 때리고, 낡은 방어구는 덜 막고, 낡은 도구는 느리게 캡니다.
남은 내구도가 `full-performance-above`(기본 80%) 이상이면 페널티 없음, 그 아래로는
0%까지 `minimum-performance`(기본 50%)로 직선 감소합니다. 예) 내구도 60% → 성능 87%.

| 대상 | 기준 | 적용 |
|---|---|---|
| 근접 공격 / 채굴 속도 | 주 손 아이템 | `attack_damage`, `block_break_speed` |
| 방어력 | 착용 방어구 **평균** | `armor`, `armor_toughness` |
| 원거리 피해 | 발사한 활·석궁·삼지창 | 투사체 기본 피해량 |

아이템 자체는 건드리지 않고 플레이어 어트리뷰트에만 걸리므로, 수리하면 성능이 그대로 돌아옵니다.
원거리는 **발사 시점** 무기 상태를 투사체에 새깁니다.

### 모루 커스텀 강화
왼쪽 칸에 장비, 오른쪽 칸에 재료. **경험치 레벨을 쓰지 않고 반복 횟수 제한도 없습니다.**
바닐라의 "수리 비용이 너무 비쌉니다" 누적 제한도 걸리지 않습니다.

| 조합 | 재료 | 효과 |
|---|---|---|
| 날 세우기 | 부싯돌 2 | 날카로움 +1 |
| 성화 각인 | 발광석 가루 3 | 강타 +1 |
| 독 바르기 | 거미 눈 3 | 벌레 죽이기 +1 |
| 기계 정비 | 레드스톤 4 | 효율 +1 |
| 철판 덧대기 | 철 블록 1 | 보호 +1 |
| 흑요석 담금질 | 흑요석 2 | 내구성 +1 |
| 숫돌 정비 | 숫돌 1 | 내구도 +25% |

조합법에 걸리지 않는 조합은 **바닐라 모루 그대로**입니다 — 같은 재료 수리, 인챈트북 합치기,
이름 변경 모두 정상 동작합니다. 내구도 페널티와 맞물려 **수리 = 성능 회복**입니다.

### 연쇄 벌목
도끼로 원목을 캐면 이어진 같은 원목이 전부 순차 제거됩니다. **가지와 대각선 줄기까지 따라갑니다**
— 참나무·정글나무 가지, 아카시아의 비스듬한 줄기, 2x2 굵은 나무 모두 한 번에 잘립니다.

번지는 범위는 두 가지로 묶여 있습니다.
- **캔 블록보다 아래로는 내려가지 않습니다** — 바닥에 깔린 원목이나 옆 나무 밑동을 파먹지 않습니다.
- **가로 반경 제한**(`max-horizontal-radius`, 기본 5) — 원목이 줄지어 있어도 옆 나무로 옮겨붙지 않습니다.

큐를 틱당 몇 블록씩만 소비하므로 대형 나무에서도 렉이 없습니다.
웅크리면 비활성, 크리에이티브 제외, `max-blocks` 상한 적용.
6면 원목(`oak_wood` 등)은 기본 목록에 없어 원목 건축물은 안전합니다.

### 근접 채팅
설정한 거리 안의 플레이어에게만 채팅이 전달됩니다. 플레이어가 입력한 `&` 색코드는
그대로 텍스트로 나가므로 채팅을 꾸미거나 위장할 수 없습니다.

### 이름표 · 플레이어 목록
머리 위 이름표와 Tab 플레이어 목록에 파티·칭호·레벨·직업이 함께 나옵니다.

```
머리 위   [푸른사슴] [강태공] Alpha Lv.6 전사
Tab 목록  [푸른사슴] [강태공] Alpha Lv.6
```

- 파티가 없거나 칭호·직업이 없으면 **그 조각만 통째로 빠집니다** — 빈 괄호가 남지 않습니다.
- 무엇을 보여줄지는 두 곳에서 따로 정합니다(기본값: 목록에는 직업 미표시).
- 스코어보드 팀 기능으로 붙이므로 **베드락(Geyser)에서도 똑같이 보이고**, 별도 패킷을
  매 틱 쏘지 않습니다. 레벨·파티·직업이 실제로 바뀔 때만 갱신됩니다.
- 접속을 끊으면 붙였던 팀도 같이 지워집니다(월드 스코어보드에 쌓이지 않음).
  다른 플러그인이 이름표를 관리한다면 `features.nameplate` 를 끄면 됩니다.

### 아이템 무게 툴팁
아이템 설명 맨 아래에 작은 회색 글씨로 `무게 8` 한 줄이 붙습니다.

- **1개당 무게**입니다. 개수와 무관한 값이라야 같은 아이템끼리 계속 겹쳐집니다.
- 바닥에 떨어진 아이템, 상자에서 꺼낸 아이템에도 같은 줄이 붙으므로 **묶음이 갈라지지 않습니다.**
- 다른 플러그인이 넣은 설명이나 플레이어가 붙인 이름은 건드리지 않고, 이 한 줄만 관리합니다.
- 무게 설정을 바꾸고 `/rpgcore reload` 하면 줄도 따라서 갱신되고, 기능을 끄면 다시 지워집니다.

### Discord 연동

서버에서 일어난 일을 디스코드 채널로 보냅니다. **봇을 만들 필요 없이 웹후크 주소 하나**면
되고, 다른 플러그인도 라이브러리도 필요 없습니다.

**설정 (2분)**

1. 디스코드에서 알림을 받을 채널 우클릭 → **채널 편집 → 연동 → 웹후크 → 새 웹후크**
2. **[웹후크 URL 복사]**
3. `config.yml` 의 `discord.webhook-url` 에 붙여넣고 `enabled: true`
4. `/rpgcore reload`

보내는 것과 그 모양:

| 알림 | 색 | 보기 |
|---|---|---|
| 서버 열림 | 초록 | 🟢 서버가 열렸습니다 · Paper 26.2 · RPGCore 2.6.0 |
| 서버 닫힘 | 빨강 | 🔴 서버가 닫혔습니다 · 가동 시간 3시간 12분 |
| 접속 / 퇴장 | 초록 / 회색 | Steve 님이 접속했습니다 · 접속 중 4명 |
| 사망 | 빨강 | 💀 Steve was slain by Zombie · Lv.23 · world |
| 레벨업 | 블러플 | ⬆️ Steve 님이 Lv.30 이 되었습니다 |
| 업적 | 금색 | 🏆 Steve 님이 [광맥왕] 을(를) 달성했습니다 · 2000G · 칭호 [광맥왕] |
| 서버 최초 업적 | 자홍 | 🥇 Steve 님이 … 을(를) 서버 최초로 달성! |

**한 줄에 하나씩, 색으로 구분합니다.** 임베드의 왼쪽 색 막대가 종류를 대신하므로 글을
읽기 전에 무슨 일인지 알 수 있고, 플레이어 머리 아이콘이 붙어서 누구인지는 얼굴로
먼저 읽힙니다. 사망은 **바닐라 사망 메시지를 그대로** 옮깁니다 — 원인과 가해자가 이미
들어 있어서 다시 쓰면 정보만 잃습니다.

#### 채널이 잠기지 않게 하는 것들

알림을 다 보내면 채널이 못 읽게 됩니다. 그래서 세 겹으로 거릅니다.

- **레벨업은 걸러서 보냅니다.** 초반 레벨은 몇 분에 한 번씩, 그것도 인원수만큼 올라옵니다.
  기본값은 `minimum-level: 10` 과 `only-multiples-of: 5` — Lv.10 밑은 보내지 않고, 그
  위로는 5의 배수만 보냅니다. **최대 레벨 도달은 이 조건과 상관없이 항상** 보냅니다.
- **업적은 게임 안 공지 규칙을 따릅니다.** 서버 전체에 알릴 만한 것(서버 최초 기록,
  칭호가 걸린 업적)만 갑니다. 자잘한 단계까지 원하면 `all-achievements: true`.
- **묶어서 보냅니다.** 0.4초 안에 생긴 알림은 한 메시지에 최대 10개까지 함께 담깁니다.
  한 전투에서 열 명이 죽으면 디스코드 메시지도 **열 개가 아니라 하나**입니다.

`events` 아래에서 종류별로 끄고 켤 수 있습니다.

#### 서버가 느려지지 않게 하는 것들

남의 서버로 HTTP 요청을 보내는 일이라, **메인 스레드는 절대 기다리지 않습니다.**

- 전송은 전용 스레드(`RPGCore-discord`)에서 합니다. Bukkit 의 비동기 스케줄러가 아닌
  이유는 파일 저장과 같습니다 — 그 스케줄러는 메인 스레드 박동에서 일을 넘기므로,
  **메인 스레드가 바쁘거나 종료 중일 때는 돌지 않습니다.** 종료 알림이 필요한 순간이
  정확히 그때입니다.
- 대기열은 상한이 있고(256건), 차면 **가장 오래된 것부터 버립니다.** 디스코드가 죽어도
  힙이 늘지 않고 호출한 쪽이 멈추지 않습니다.
- 429(속도 제한)는 디스코드가 알려준 시간만큼 기다렸다가 다시 보냅니다. 404/401
  (지워졌거나 잘못된 웹후크)는 재시도하지 않고 **경고를 한 번만** 남깁니다.

#### 주소는 비밀번호입니다

웹후크 주소를 아는 사람은 누구나 그 채널에 **서버인 척 글을 쓸 수 있습니다.**

- 플러그인은 이 주소를 **로그에도, `/rpgcore check` 에도 찍지 않습니다.** 점검 화면에는
  `웹훅 설정됨` 이라고만 나옵니다.
- 실수로 공개했다면 디스코드에서 그 웹후크를 지우고 새로 만드세요. 주소만 바꾸면 됩니다.
- 플레이어 이름과 업적 이름은 디스코드 마크다운으로 **이스케이프해서** 보내고, 모든
  메시지에 `allowed_mentions` 를 비워 보냅니다. 이름에 `@everyone` 이 들어 있어도
  서버 전체에 알림이 가지 않습니다.

> **한쪽 방향입니다** (마인크래프트 → 디스코드). 디스코드에 친 글을 게임 채팅으로
> 가져오려면 상시 연결된 봇이 필요하고, 그건 웹후크로 되는 일이 아닙니다.

### UI
- `/menu` (별칭 `/메뉴`) — 허브. 아래 화면 전부로 이동합니다.
- `/stats` (별칭 `/rpg`, `/rpgstats`) — 상자 GUI. 스탯 배분, 직업, 장비 상태, 모루 조합법 목록.
- `/auction` (별칭 `/ah`, `/경매`) — 경매장. 45칸씩 쪽 넘김, 내 물건 보기, 우편함 받기.
- `/job` — 직업 선택 GUI. 잠긴 직업은 회색으로 표시됩니다.
- 액션바 HUD — 레벨 / HP / XP / 무게. 장비가 닳았을 때만 `GEAR 87%` 구간이 추가됩니다.

## 설정

설정은 `plugins/RPGCorePlugin/` 안의 **파일 3개**로 나뉩니다. 목적이 달라서 나눠 뒀으니,
바꾸고 싶은 게 어디 있는지만 알면 됩니다.

| 파일 | 무엇이 들어 있나 | 언제 여나 |
|---|---|---|
| **`settings.yml`** | 최대 레벨, 경험치 곡선, 인챈트 한계, 기능 on/off | **대부분 여기만 보면 됩니다** |
| **`jobs.yml`** | 직업 정의 | 직업을 만들거나 고칠 때 |
| **`achievements.yml`** | 업적과 그 보상·칭호 | 목표를 만들거나 고칠 때 |
| **`collection.yml`** | 도감 분류와 수집 대상 | 도감에 항목을 넣을 때 |
| `config.yml` | 아이템 무게 분류, 모루 조합법, 벌목 대상, 골드, 대결, GUI, 채팅 | 세부 조정이 필요할 때 |

> `records.yml` 은 플러그인이 직접 씁니다. '서버 최초' 업적을 누가 가져갔는지 담겨
> 있으니 손으로 고치지 마세요. 지우면 그 기록이 다시 열립니다.

고친 뒤 **`/rpgcore reload`** 하면 재시작 없이 반영됩니다.

### settings.yml — 자주 바꾸는 것

```yaml
level:
  max: 0                # 최대 레벨. 0 이면 제한 없음
  xp-base: 80           # 레벨 2 가 되는 데 필요한 XP
  xp-growth: 30         # 레벨이 오를 때마다 추가로 붙는 XP
  xp-multiplier: 1.022  # 레벨당 곱해지는 배수
  points-per-level: 1
  starting-points: 5

xp-sources:
  per-mob-kill: 15
  per-tree-log: 2

enchant:
  respect-vanilla-limits: false   # true 면 바닐라 최대 레벨까지만
  max-level: 255                  # 위가 false 일 때의 상한

features:               # 끄면 관련 명령어도 막힙니다
  jobs: true
  parties: true
  trading: true
  leaderboard: true
  tree-felling: true
  durability-scaling: true
  anvil-recipes: true
  proximity-chat: true
  hud: true
  nameplate: true         # 머리 위 이름표
  tablist: true           # 플레이어 목록(Tab)
  item-weight-lore: true  # 아이템 설명의 무게 한 줄
  achievements: true      # 업적과 칭호
  collection: true        # 수집 도감
  duels: true             # 1:1 대결
```

**최대 레벨** — `level.max` 에 닿으면 더 이상 XP 가 쌓이지 않습니다. 남은 XP 를 쌓아두지 않으므로,
나중에 상한을 올려도 전원이 한꺼번에 레벨업하는 일은 없습니다.

**레벨 배수** — 다음 레벨까지 필요한 XP 는 이렇게 계산됩니다.

```
(xp-base + (현재레벨-1) × xp-growth) × (xp-multiplier ^ (현재레벨-1))
```

`xp-base: 80`, `xp-growth: 30` 기준으로 배수만 바꿔 보면:

| xp-multiplier | Lv2 | Lv10 | Lv20 | Lv50 |
|---|---|---|---|---|
| `1.0` (직선) | 80 | 320 | 620 | 1,520 |
| `1.022` (**기본**) | 80 | 380 | 917 | 4,320 |
| `1.05` (가파름) | 80 | 472 | 1,492 | 15,809 |
| `1.5` (아주 가파름) | 80 | 8,201 | 916,292 | 4,300억 |

**인챈트 한계** — 모루 커스텀 강화로 올릴 수 있는 상한입니다.
`respect-vanilla-limits: true` 면 날카로움 5, 보호 4 처럼 바닐라 최대치에서 멈춥니다.
`false` 면 `max-level`(최대 255)까지 계속 올라갑니다. 조합법마다 `max-level` 을 따로 적으면
**둘 중 낮은 쪽**이 적용됩니다.

### jobs.yml — 직업 만들기

`list:` 아래에 블록을 하나 더 붙이면 끝입니다. 코드 수정은 필요 없습니다.

```yaml
allow-change: true        # false 면 한 번 고르면 못 바꿈
change-cost-levels: 0     # 변경 시 소모할 바닐라 경험치 레벨
menu-title: "&8직업 선택"

list:
  mage:                          # 이게 /job <id> 의 id 입니다
    name: "&5마법사"
    icon: minecraft:blaze_rod
    description:
      - "&7설명 줄."
    min-level: 15                # 이 RPG 레벨부터 선택 가능
    stat-bonus:                  # 직접 찍은 포인트 위에 더해짐
      luck: 5
      dex: 2
    weight-bonus: 0              # 최대 소지무게에 더하기
    xp-multiplier: 1.2           # 획득 경험치 배율
    attributes:
      add:                       # 고정값 더하기
        max_health: 2
      multiply:                  # 합계에 비율 곱하기 (0.1 = +10%)
        movement_speed: 0.05
```

`attributes` 에는 **바닐라 어트리뷰트 ID 를 그대로** 씁니다:
`max_health` `attack_damage` `attack_speed` `armor` `armor_toughness`
`movement_speed` `knockback_resistance` `block_break_speed` `luck` `jump_strength` 등.
이 서버에 없는 ID 는 경고만 남기고 무시하므로 설정이 통째로 깨지지 않습니다.

| `party` | `max-size`, `name-max-length`, `friendly-fire`, `chat-prefix`(`%party%`), `xp.*` |

#### 아이템 목록 쓰는 법

`weight.tiers.*.items`, `tree-felling.logs` / `tools`, `anvil` 의 `target` 은 모두 같은 문법입니다.

```yaml
items:
  - minecraft:stone            # 낱개 ID
  - '#minecraft:planks'        # 바닐라 태그 (그 태그에 속한 전부)
  - '#myserver:custom_gear'    # 서버에 깔린 다른 데이터팩 태그
```

이 서버 버전에 없는 항목은 **경고만 남기고 건너뜁니다.** 목록 전체가 죽지 않으므로
설정 하나로 여러 버전을 커버할 수 있습니다.

#### 모루 조합법 추가하기

```yaml
anvil:
  recipes:
    my-recipe:                                        # 아무 키나 가능
      name: "&b내 조합"                                # /rpgcore recipes 표시용
      target: ['#minecraft:enchantable/sharp_weapon']  # 왼쪽 칸에 올 수 있는 것
      ingredient: minecraft:flint                      # 오른쪽 칸 재료
      ingredient-amount: 2
      repair-percent: 0                                # 최대 내구도의 N% 회복
      level-cost: 0                                    # 소모할 경험치 레벨
      enchantments:
        sharpness: 1                                   # 1회당 올릴 레벨
```

- 자주 쓰는 대상 태그: `#minecraft:enchantable/sharp_weapon`(검·도끼),
  `#minecraft:enchantable/mining`(채굴 도구), `#minecraft:enchantable/armor`(방어구),
  `#minecraft:enchantable/durability`(내구도 있는 장비 전부).
- **재료 선택 주의**: 그 장비의 바닐라 수리 재료(철 갑옷 + 철 주괴 등)를 쓰면 바닐라 수리를
  덮어씁니다. 기본 조합법이 철 '주괴' 대신 철 '블록', 숫돌을 쓰는 이유입니다.

#### 이름표 / 플레이어 목록 꾸미기

```yaml
weight:
  lore-format: "&8무게 %weight%"   # 아이템 툴팁 한 줄. ""(빈 값)이면 표시 안 함

display:
  # 조각별 서식. %party% %title% %level% %job% 이 바뀝니다.
  party-format: "&8[&d%party%&8]"
  title-format: "%title%"          # 칭호 문구는 achievements/collection.yml 에서 정합니다
  level-format: "&7Lv.&e%level%"
  job-format: "&b%job%"

  nameplate:        # 머리 위
    show-party: true
    show-title: true
    show-level: true
    show-job: true
  tablist:          # Tab 목록
    show-party: true
    show-title: true
    show-level: true
    show-job: false
```

- 파티와 칭호는 **이름 앞**, 레벨과 직업은 **이름 뒤**에 붙습니다. 사이 공백은 자동이라
  서식에 넣지 않아도 됩니다.
- 해당 정보가 없으면(파티 없음·직업 없음) 그 조각은 아예 빠집니다.
- 서식을 `""` 로 비우면 양쪽 모두에서 그 조각이 사라집니다.
- 이름표 자체를 끄려면 `settings.yml` 의 `features.nameplate`, 목록은 `features.tablist`,
  무게 툴팁은 `features.item-weight-lore` 를 `false` 로 두세요.

#### 업적 만들기 (achievements.yml)

```yaml
announce-to-server: true      # 칭호가 걸린 업적/서버 최초 업적을 전체 공지

achievements:
  my-goal:                    # 아무 키나 가능. 칭호 id 로도 쓰입니다

    description: "몬스터 100마리 처치"

    title: "&e[사냥꾼]"        # 비우면 보상만 주고 칭호는 없음
```

측정 기준(`type`)은 `mob-kills`, `blocks-mined`, `ores-mined`, `logs-chopped`,
`fish-caught`, `duels-won`, `gold-earned`, `collected`, `level` 입니다.
없는 기준을 적으면 그 업적만 건너뛰고 **쓸 수 있는 목록을 로그에 적어 줍니다.**

무엇을 '광석'과 '원목'으로 셀지는 `config.yml` 에서 바꿀 수 있습니다. 비워 두면
바닐라 기본값(광석 19종 / 원목 44종)이고, 모드나 데이터팩 블록을 세고 싶을 때만 채웁니다.

```yaml
progress:
  ore-blocks: []    # 예: ['#minecraft:iron_ores', 'mypack:mithril_ore']
  log-blocks: []
```

기준값은 전부 스코어보드(`rpgcore.kills` 등)에 저장되므로 `/scoreboard players get`
으로 직접 확인할 수 있고, 오프라인 플레이어의 값도 남아 있습니다.

## 베드락(Geyser/Floodgate) 호환

모든 로직이 서버 사이드라 **베드락에서 별도 설정 없이 그대로 동작합니다.**
UI도 일반 상자 GUI 하나만 쓰므로 Geyser가 알아서 베드락 화면으로 번역합니다.
아이콘도 양쪽에서 동일하게 렌더되는 것만 씁니다.

유일한 차이는 **점프력 페널티**입니다. 베드락에는 플레이어 jump_strength 어트리뷰트가
없어 적용되지 않습니다. 이동속도 페널티와 허기는 그대로 걸립니다.

## 데이터 저장

플레이어 상태는 `rpgcore.*` **바닐라 스코어보드 오브젝티브**에 미러링되어 월드와 함께
저장됩니다. 별도 데이터 파일이 없고, 다른 데이터팩이나 커맨드 블록에서 읽을 수도 있습니다.

```
/scoreboard players get <player> rpgcore.level
```

접속 중인 플레이어의 값을 손으로 고치는 것은 소용이 없습니다. 플러그인은 값이 실제로
바뀔 때만 기록하므로 잠시 남아 있는 것처럼 보여도, 그 값이 다음에 바뀌는 순간과 접속을
종료할 때 덮어써집니다. 오프라인일 때 고치거나 `/rpgcore givexp` · `/rpgcore givegold` ·
`/rpgcore reset` 을 쓰세요.

**직업**만은 문자열이라 스코어보드에 담을 수 없어, 플레이어의 바닐라 playerdata 안에
저장됩니다(PersistentDataContainer). 역시 별도 파일이 생기지 않습니다.

```
/data get entity <player> data
```

**업적·칭호·도감**도 문자열이라 같은 곳(PersistentDataContainer)에 들어갑니다.
진행도 카운터(`rpgcore.kills`, `rpgcore.ores` …)와 **골드**(`rpgcore.gold`)는 정수라
스코어보드에 그대로 미러링됩니다. '서버 최초' 업적의 주인만 `records.yml` 에 남습니다.

**파티**는 이름·구성원을 가진 그룹이라 스코어보드에도 개인 데이터에도 맞지 않아,
`plugins/RPGCorePlugin/parties.yml` 에 저장됩니다. 바뀐 내용은 1초 안에 기록되므로
서버가 갑자기 내려가도 남습니다(아래 "파일이 언제 쓰이는가" 참고). 진행 중인 거래는 저장되지 않고, 서버 종료 시 물건을
주인에게 돌려준 뒤 정리됩니다.

### 파일이 언제 쓰이는가
길드·경매·파티·우편함은 **바뀔 때마다 즉시 쓰지 않고** 메모리에 모아 두었다가 기본 1초마다
한 번, **메인 스레드가 아닌 전용 스레드**에서 씁니다(`config.yml` 의 `persistence`).

실제로 재 보면 길드 50개가 각각 54칸 보관함을 채운 상태에서 파일 한 번 쓰는 데 **65ms** —
서버 틱(50ms)보다 깁니다. 보관함을 닫을 때마다, 금고에 넣을 때마다, 전쟁이 끝날 때마다 그
비용을 그 자리에서 내고 있었습니다. 시간이 어디로 가는지 쪼개 보면 자료를 모으는 데 1ms 도
안 걸리고 **YAML 텍스트로 뽑는 데 전부** 쓰입니다. 그래서 두 작업을 갈라 놓았습니다 — 모으는
쪽은 메인 스레드(살아 있는 인벤토리를 읽어야 하므로), 뽑아서 쓰는 쪽은 별도 스레드.

한 틱 안에 500번 바뀌어도 쓰기는 한 번입니다. 네 파일이 **같은 틱에 함께** 쓰이는 것도
의도된 것입니다 — 경매 낙찰과 그 대금이 들어간 우편함은 한 거래이고, 둘을 다른 순간에 쓰면
그 사이에 크래시가 났을 때 어디에도 없는 아이템이 생깁니다.

대신 크래시 시 최대 1초어치 변경을 잃을 수 있습니다. `flush-interval-ticks` 로 조절합니다.
서버 종료 시에는 그 자리에서 동기적으로 씁니다.

길드는 `plugins/RPGCorePlugin/guilds.yml` 에 저장됩니다. 명단·영지·금고·투자액·진행 중인
전쟁·전쟁 재사용 대기시간, 그리고 **공동 보관함 내용물까지 같은 파일에** 들어갑니다 — 누가 열 수 있는지를 적은 명단과 그 안의 물건이 서로
어긋날 여지를 만들지 않기 위해서입니다. 보관함은 칸 번호째로 기록하므로 정리해 둔 배치가
그대로 유지됩니다.

경매 진행 상황은 `plugins/RPGCorePlugin/auctions.yml`, 아직 전달하지 못한 물건과 골드는
`plugins/RPGCorePlugin/mailbox.yml` 에 저장됩니다. 이 파일들이 존재하는 이유가 "서버가
곱게 안 내려간 경우"이므로 종료만 믿지 않고 **바뀐 뒤 1초 안에** 기록합니다.

경매에 올라간 물건과 최고 입찰 골드는 각각 판매자와 입찰자에게서 실제로 빼 온 것이므로,
`auctions.yml` 은 캐시가 아니라 남의 재산 보관 장부입니다. 읽다가 깨진 항목이 있으면
조용히 건너뛰지 않고 `SEVERE` 로 남깁니다.

어트리뷰트 모디파이어 네임스페이스는 플러그인 이름에서 나오므로 `rpgcoreplugin:*` 입니다.

```
/attribute <player> minecraft:movement_speed modifier value get rpgcoreplugin:weight_speed
```

고친 버그:

- **길드 초대가 접속 종료 시 정리되지 않았습니다.** 파티·대결·거래는 모두 정리하는데 길드만
  빠져 있었고, 만료 처리는 대상이 `/guild accept` 를 쳐야만 돌았습니다 — 로그아웃한 사람이
  절대 하지 않는 바로 그 행동입니다.
- **작물 성장 처리가 이벤트 상태를 두 번 읽고 있었습니다.** `getBlockData()` 는 사본을
  주므로, 사본을 받아 온 그 상태 객체에 다시 써야 합니다. 한 번만 잡도록 고쳤습니다.
- **`flushNow()` 가 쓰기 스레드와 같은 파일을 동시에 쓸 수 있었습니다** (제가 이번에 넣은
  버그입니다). 두 스레드가 한 파일을 쓰면 둘 중 오래된 쪽이 남는 게 아니라 **아무것도 안
  남습니다.** 쓰기 구간에 잠금을 걸고, 종료 쓰기 이후에는 대기 중이던 쓰기를 버립니다.
- **Bukkit 비동기 스케줄러로는 안 됐습니다** (역시 이번에 넣은 버그). 그 스케줄러는 메인
  스레드 하트비트에서 작업을 꺼내므로, 메인 스레드가 바쁘거나 멈춰 있거나 내려가는 중이면
  — 즉 백그라운드 쓰기가 가장 필요한 순간에 — 쓰기가 시작되지 않습니다. 검증에서 5초를
  기다려도 파일이 안 생겨 발견했고, 전용 스레드로 바꿨습니다.

### 길드전·투자 검증

전쟁과 금고도 같은 방식으로 실제 코드를 돌렸습니다. 검사 항목 총 **97개, 전부 통과**,
기동·리로드·종료 예외 0건 · SEVERE 0건.

- **전쟁 단계**: 선포 직후는 준비 중(교전 아님), 준비 시간이 지나면 교전, 종료 시각이
  지나면 끝. 양쪽 어디서 조회해도 같은 전쟁을 찾아냄
- **폭발 보호가 단계를 따라감**: 준비 중에는 영지가 여전히 보호되고, 교전이 시작되면
  풀리며, 전쟁이 끝나면 다시 걸림
- **전리품 계산**: 금고 500 vs 8,000 에서 승자 8,500 / 패자 0. 두 금고의 합이 전후로
  동일 — 전쟁으로 골드가 생기지도 사라지지도 않음. 승부는 한 번만 확정되고 재대결은
  대기시간에 막힘
- **투자 사다리**: 미투자는 기본 반경, 1블록 값에서 1 모자라면 안 넓어지고 남은 금액이
  정확히 1, 3블록 값이면 +3, 한계를 넘겨 투자해도 최대에서 멈추고 더 팔 것이 없음
- **넓어진 영지가 실제로 보호됨**: 투자 후 청크 색인이 새 바깥 테두리까지 답하고, 그
  한 블록 밖에서는 답하지 않음 (색인을 갱신하지 않았다면 돈 주고 산 땅이 무방비)
- **깃발 간격이 성장을 막지 않음**: 최대 반경 기준(208블록)으로 자리를 잡으므로 두 영지가
  모두 최대까지 커져도 겹치지 않음

지속성 계층을 통째로 바꿨으므로 검사도 늘렸습니다 — 총 **109개 전부 통과**. `save()` 만으로는
디스크를 건드리지 않고, 플러시하면 쓰이며, 인챈트된 아이템이 보관함 칸 번호·개수까지 그대로
돌아오고, 우편함 항목도 비동기 쓰기를 건너 살아남는 것을 확인했습니다.

사람이 직접 해 봐야 하는 것 (전쟁): `/guild war` 로 선포한 뒤 실제로 상대 깃발을 부숴
승리 처리가 도는지, 교전 중에 상대 영지 블록이 정말 캐지는지. 블록 파괴 이벤트와 살아
있는 Player 가 필요한 부분입니다.

### 2.5.0 — 콘텐츠 확장과 밸런스 검증

콘텐츠를 대량으로 넣으면 **설정 파일이 조용히 반쯤만 읽히는 것**이 가장 흔한 사고입니다.
이름이 틀린 아이템 하나가 경고 한 줄만 남기고 넘어가면, 다 모을 수 없는 도감이
영원히 미완성으로 남습니다. 그래서 깨끗한 서버에 새로 깔아 **기동 로그의 WARN 이
0줄**이 될 때까지 맞췄습니다.

```
[RPGCorePlugin] Weight table loaded: 280 materials
[RPGCorePlugin] Anvil recipes loaded: 16.
[RPGCorePlugin] Jobs loaded: 15.
[RPGCorePlugin] Achievements loaded: 41.
[RPGCorePlugin] Collection log loaded: 20 categories, 363 entries.
[RPGCoreVerify] ===== RPGCORE VERIFY: 114/114 passed =====
```

실제로 서버가 잡아낸 것들 — 전부 **추측으로는 찾지 못했을** 것들입니다.

- `#minecraft:corals` · `#minecraft:coral_blocks` · `#minecraft:base_stone_overworld` 는
  **블록 태그로만 존재**합니다. 도감은 아이템 태그에서 찾으므로 산호 분류가 통째로
  비어 `no items resolved - skipped` 로 빠져 있었습니다 → 낱개 ID 로 교체
- `#minecraft:music_discs` · `#minecraft:tall_flowers` · `#minecraft:enchantable/sword`
  는 **이 버전에 아예 없는 이름**이었습니다 → 디스크 21종을 낱개로, 모루 조합법은
  `#minecraft:swords` 로 교체
- **`minecraft:chain` 이 `minecraft:iron_chain` 으로 바뀌어 있었습니다.** 구리 사슬이
  추가되면서 이름이 갈라진 것으로, 바닐라 지식으로는 틀린 줄 알 수 없습니다
- `crimson_stem` · `warped_stem` 은 `#minecraft:logs` 에 들어 있어 원목 분류와 겹쳤습니다
  → 네더 분류에서 빼고 네더 전용 블록으로 교체 (한 아이템은 한 분류에만 들어갑니다)

밸런스 쪽은 수치를 고친 뒤 **기존 114개 검사를 그대로 다시 돌려** 스탯·지속성·전쟁·경매
동작이 깨지지 않았음을 확인했습니다.

사람이 직접 해 봐야 하는 것: 소프트캡을 넘긴 스탯이 `/stats` 창에 실제로 어떻게 보이는지,
LUCK 2배 보상 액션바가 뜨는지, 3단계 직업의 체력 페널티가 하트 칸으로 체감되는지.
화면과 살아 있는 Player 가 필요한 부분입니다.

### 2.6.0 — Discord 연동 검증

남의 서버로 HTTP 를 보내는 코드는 **읽어서 맞는지 알 수 없습니다.** 그래서 디스코드
웹후크 흉내를 내는 작은 수신 서버를 띄우고 실제 소켓에 대고 돌렸습니다 — 검사 **22개
추가, 총 136개 전부 통과**.

실제로 잡힌 요청 기록입니다.

```
[webhook]   embeds=1   mentions_off=True  ['🟢  서버가 열렸습니다']
[webhook]   embeds=1   mentions_off=True  ['💀  "quoted" \backslash\ 한글 @everyone']
[webhook]   embeds=10  mentions_off=True  ['batched 0' ... 'batched 9']
[ratelimit] embeds=1   mentions_off=True  ['rate limited']      <- 429
[ratelimit] embeds=1   mentions_off=True  ['rate limited']      <- 재전송, 성공
[gone]      embeds=3   mentions_off=True  ['to a deleted webhook 0' ...]
[webhook]   embeds=1   mentions_off=True  ['🔴  서버가 닫혔습니다']
```

- **종료 알림이 실제로 도착합니다.** 전송 스레드가 데몬이라, 큐에 넣기만 하면 JVM 이
  먼저 끝나 아무도 못 봅니다. 마지막 줄이 그게 아님을 보여줍니다
- **10개가 1개 요청**으로 나갔습니다 (`batched 10 events into 1 request(s)`)
- **429 는 기다렸다가 재전송**, **404 는 3건을 1요청으로 시도하고 재시도 없음**
- **디스코드가 죽어 있어도 막지 않습니다**: 응답 없는 주소로 2,000건을 쌓는 데 **5ms**
- 따옴표·역슬래시·제어문자·한글·`@everyone` 이 섞인 메시지를 **진짜 JSON 파서가
  받아들였고**, `allowed_mentions` 가 모든 메시지에서 비어 있었습니다

주소가 새지 않는지는 별도로 확인했습니다 — 웹후크에 눈에 띄는 가짜 토큰을 넣고 기동 ·
`/rpgcore check` · `/rpgcore reload` 를 돌린 뒤 콘솔 전체를 뒤져 **0건**.

사람이 직접 해 봐야 하는 것: 실제 디스코드 채널에서 색 막대와 머리 아이콘이 의도대로
보이는지, 그리고 접속·사망·레벨업·업적 알림의 문장이 실제 플레이어 이름으로 어떻게
읽히는지. 살아 있는 Player 와 진짜 웹후크가 필요한 부분입니다.
